# 931743 动量信号设计

## 1. 目标与边界

本项目每日观察 **中证半导体材料设备主题指数（931743）** 自身的动量与趋势，保留完整历史信号，并生成可离线查看、可由 GitHub Pages 发布的研究报告。

不再维护板块 ETF 候选池、跨标的排名或全市场强弱比例；931743 的信号不代表 A 股整体撤退判断。不提供券商执行、实盘账户、邮件或微信通知，也不自动买入货币基金或国债 ETF。

代码从旧轮动框架收敛为单指数，但保留已使用的评分、1/3 目标、持有漂移、预警调仓检查及冷却语义。它不是重新优化后的交易策略。

## 3. 行情与时间边界

### 3.1 来源与校验

- 接口：`https://www.csindex.com.cn/csindex-home/perf/index-perf`，参数为 `indexCode=931743`、`startDate`、`endDate`。
- 请求起点固定为 `2023-07-19`。这是已核对的完整 OHLC 交易日，避免接口在更早或非交易日起点插入图表补点。
- 每次联网重新获取全量日线，无 pickle 缓存、旧数据回退或相邻仓库依赖。
- 校验成功状态、非空数据、指数代码、日期合法且不重复、工作日、请求区间，以及首条数据覆盖请求起点。
- 校验数值有限、`0 < low <= min(open, close) <= max(open, close) <= high`、量额非负；成交额由亿元转换为元，并再次检查有限性。
- 校验通过后按日期升序返回。未接入交易所日历，无法仅凭此校验保证区间内每个应有交易日都已返回。

### 3.2 完整日线与新鲜度

时间统一为 `Asia/Shanghai`。默认请求截止日为北京时间今天；15:30 前，实际取数截止日最多为昨天。`--as-of` 不可晚于今天，也不能早于固定信号起点。

状态按以下优先级判断：

1. 请求日期早于今天：`historical`，显示请求截止日与最后可用日线。
2. 今天是工作日且尚未到 15:30：`awaiting_close`，不称此前数据为今日收盘判断。
3. 最后可用日线早于请求日期：`no_current_bar`，可能休市或源数据未发布。
4. 否则为 `current`。

不会补造 K 线、节假日信号或未来成交。生成时间与行情时间分开显示。

## 4. 动量评分

以下窗口均按返回日线条数计算，不是自然日。令 `C[t]` 为第 t 根日线收盘价：

```text
R[w] = (C[t] / C[t-w] - 1) × 100
M = 0.40 × R[5] + 0.30 × R[10] + 0.20 × R[20] + 0.10 × R[60]
trend_ok = C[t] > 最近10根收盘价的均值
V = 最近20个日收益率绝对值的均值，单位为百分数
P = 1                              当 V <= 5
P = max(0, 1 - (V - 5) / 5)        当 V > 5
adjusted_momentum = round(M × P, 2)
```

`V` 是平均绝对日收益，不是收益标准差；`V >= 10` 时惩罚系数为 0。输出中的原始动量和惩罚系数也各自保留两位小数，但调整后动量用**未先舍入的 M 与 P**相乘后再舍入。

风控使用两位小数的调整后动量，所以微小正值舍入成 0 时也会清仓。趋势要求严格高于均线，等于均线不通过。评分至少需要 `max(MOMENTUM_WINDOWS) + 5 = 65` 根日线。

## 5. 收盘决策

### 5.1 风险判断

- **紧急风控**：`adjusted_momentum <= 0`，或 `trend_ok == False`。
- **预警**：最近 5 次调整后动量严格递减，即 4 次相邻下降；相等会打断递减。
- 两者可以同时成立，紧急风控优先。

这与原单指数调用的动作条件等价：只有一个标的时，“正动量比例”和“均线上方比例”只可能为 0 或 1，旧市场广度阈值实际退化为上述布尔判断。旧的平均动量也就是指数自身动量，因此不再保留 ETF 池、比例阈值或重复排名计算。

### 5.2 动作与目标

| 条件 | 原始动作 | 收盘目标权重 | 含义 |
|---|---|---|---|
| 紧急风控 | `clear_all` | 0 | 下一实际返回交易日开盘清仓；空仓也保留该动作 |
| 无紧急风控，但有预警 | `reduce_half` | 1/3 | 检查目标，可能补买或不成交 |
| 条件正常，当前空仓 | `rebalance` | 1/3 | 下一实际返回交易日开盘建仓 |
| 条件正常，已有持仓 | `hold` | 1/3 | 不执行调仓，实际权重可偏离目标 |

`TARGET_WEIGHT = 1 / 3` 明确表达仓位，不再借“最多持有 3 只”配置推导单指数权重。保留 `reduce_half` 这个历史动作值以连续解释输出记录，但它**不是减半指令**；高于目标时不卖出差额。

### 5.3 冷却

冷却计时基准为清仓指令的**执行交易日**，不是信号日。即使本来空仓，下一交易日执行 `clear_all` 也会重置 `last_clear_execution_date`。

当收盘日期与最近清仓执行日期相差少于 3 个自然日时，拦截 `rebalance` 和 `reduce_half`，有效动作改为 `hold`、目标为 0；`clear_all` 和原本的 `hold` 不被拦截。周末计入间隔，连续空仓清仓指令可能不断延后重新入场。

逐日记录同时保留 `raw_action`、`effective_action`、`cooldown_active` 和 `cooldown_blocked`，避免把未通过冷却的入场条件当作实际成交。

## 6. 历史重放与模拟记账

### 6.1 固定起点与日内顺序

信号起点固定为 `2024-09-29`，首个分析交易日为 `2024-09-30`。每次更新只延长历史，不将起点随今天向前滚动。

起点前至少需要 65 根预热日线。预热期间计算评分、风险和冷却，账户始终保持全现金，不计入分析窗口的成交和权益；起点前最后一个收盘指令可以在窗口内首个开盘执行。

每根日线按顺序处理：

1. 在开盘处理上一根日线留下的指令，必要时重置清仓日期。
2. 模拟成交、扣费，更新现金与指数单位。
3. 用当日收盘价计算费用后权益和实际仓位。
4. 仅用截至当日的数据评分，计算风险和收盘动作，再检查冷却。
5. 记录逐日状态及需要执行的事件，把收盘指令留给下一根返回日线。

不使用当日收盘信号在当日开盘成交。最新日线指令如果没有下一根日线，其执行日、开盘价和成交价保持未知。接口若漏掉一个交易日，模拟只能使用下一实际返回日线，而不是自行推断价格。

### 6.2 资金、费用与仓位

初始现金为 100,000；佣金率 `c = 0.0003`，滑点 `s = 0.001`。使用分数指数单位，现金不计息。令开盘价为 `O`、已有单位为 `q`：

```text
开盘权益 E = cash + q × O
买入成交价 = O × (1 + s)
拟补买单位 Δq = E × target_weight / 买入成交价 - q
买入现金流 = -Δq × 买入成交价 × (1 + c)
卖出成交价 = O × (1 - s)
清仓现金流 = q × 卖出成交价 × (1 - c)
收盘权益 = cash + q × close
```

只有补买单位大于 `1e-10` 且现金足以支付成交额和佣金才买入。建仓和预警都使用这条规则；不会为了回到 1/3 而部分卖出，`hold` 更不会调仓。滑点已体现在成交价中，另行展示的滑点成本不再次扣款。

每日收益为费用后收盘权益相对前一日权益的变化；首日相对初始资金计算。回撤以初始资金和已记录收盘权益的历史峰值为基准。总收益是期末权益相对初始资金的变化；不输出旧回测的线性年化或沪深 300 超额表现。

期末未平仓市值计入权益。已结束持仓周期汇总首次买入及补买的含费成本、清仓净收入、净收益和入场至离场的交易日序号差，不将未平仓周期冒充已实现收益。

## 7. 报告与输出契约

| 文件 | 内容 |
|---|---|
| `index.html` | 完整历史页面，内嵌 CSS、SVG 和筛选脚本 |
| `summary.json` | 元数据、数据状态、参数、汇总、`daily` / `events` / `trades` / `round_trips` |
| `daily_signals.csv` | 每个分析交易日一行，包括空仓、重复清仓和冷却拦截 |
| `events.csv` | 收盘买卖与调仓检查，状态为 `pending`、`executed` 或 `no_fill` |
| `trades.csv` | 实际发生的假设性买卖，不包含无成交指令 |
| `round_trips.csv` | 已结束持仓周期 |
| `ohlc_history.csv` | 包含预热期的全部返回行情 |
| `.nojekyll` | Pages 静态发布标记 |

`parameters.target_weight` 表示目标权重，`momentum_decline_observations` 表示连续下降判断使用的评分数；不再输出多标的 `max_holdings` 参数。

成交事件区分建仓 `buy`、补买 `add`、卖出 `sell`；预警或调仓指令尚未成交时显示 `rebalance_check`。空仓时重复 `clear_all` 只保留在逐日状态，不新增卖出事件。`events` 的数量因此不必等于 `trades`。

页面默认保留全部记录，筛选只改变可见行，不删改下载文件。外部数据按文本／属性转义后嵌入 HTML；页面无外部脚本和异步取数，数据源外链仅供核查。

## 8. 发布、失败语义与验证

工作流在周一至周五北京时间 18:00、推送到 `main` 或手动触发时运行，且只在默认分支构建。构建失败则不上传新的 Pages artifact，部署依赖构建成功；线上会继续保留上一份成功报告，而不是证明今日已更新。

取数、分析、HTML 渲染和 JSON/CSV 序列化全部成功后才开始写输出文件。**本地写出不是整个目录的原子替换**，磁盘写入中途失败可能留下部分更新；但 CLI 返回非零，workflow 不会把它部署为成功报告。缺失今日行情与网络失败是不同情况：前者可生成明确标注过期状态的报告，后者直接失败，不回退旧数据。

测试覆盖解析错误、截止日、次日开盘及跳空、清仓冷却、单指数风控边界和正常持仓漂移。运行方式见 [README](../README.md)。修改评分、风险或执行代码时，应另用固定行情对比逐日动作、实际成交、费用和权益，并实际生成报告；页面改动需用浏览器检查展示与筛选。工作流本地可运行不等于 GitHub Pages 已完成部署。

## 9. 研究限制

这是指数方向研究，不是可交易 ETF 的执行系统。没有真实 ETF 的跟踪误差、整数份额、涨跌停、停牌、流动性、T+1 库存和委托撮合建模。次日开盘、滑点与佣金均是假设；数据源修订也可能改变历史重放。任何模拟收益都不构成投资建议。
